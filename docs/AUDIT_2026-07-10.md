## P0 — блокирует production-readiness

### P0-1. Biometric login — compile error / security theater

**Файлы:** `ui/screens/AuthScreen.kt:432`, `ui/viewmodel/AuthViewModel.kt:237`

```kotlin
// AuthScreen.kt:431-432 — вызов с 2 аргументами
val cipher = result.cryptoObject?.cipher
viewModel.loginWithBiometrics(selectedBioUserPhone, cipher)

// AuthViewModel.kt:237 — сигнатура с 1 аргументом, cipher НЕ используется
fun loginWithBiometrics(phone: String) {
    // ...
    val result = authRepository.verifyCurrentSession()
}
```

**Проблема:** Compile-time breaking bug. Если компилируется — cipher игнорируется, refresh token не расшифровывается, биометрия не добавляет защиты.

**Фикс:** Добавить параметр `cipher: Cipher` в `loginWithBiometrics`, использовать его для расшифровки refresh token через `BiometricCryptoHelper.decryptRefreshToken(encryptedBlob, cipher)`.

### P0-2. WebSocket контракт-mismatch с backend

**Файлы:** `utils/ClinicWebSocketClient.kt`, `utils/WsEventModels.kt`, `data/realtime/RealtimeManager.kt`

| Mobile client ожидает | Backend отправляет |
|---|---|
| `wss://host/ws/queue` без query params | `wss://host/ws/queue?department=...&date=...` (обязательные query params) |
| Отправляет `{"type":"subscribe","channel":"my_queue"}` handshake | Backend игнорирует handshake |
| Парсит поле `"event"` в сообщениях | Backend шлёт поле `"type"` |
| Не обрабатывает `{"type":"ping",...}` heartbeat | Backend шлёт ping каждые 30s |
| Не обрабатывает `{"type":"queue.connected",...}` | Backend отправляет при подключении |

**Следствие:** WebSocket подключается к room `"::"` (пустые department+date), все события молча дропаются. **Реалтайм-обновления полностью неработоспособны.**

**Фикс:** Полностью переделать WS-интеграцию — добавить query params, переименовать `event` → `type` в парсинге, обработать ping/queue.connected, удалить subscribe-handshake, обновить 13 unit-тестов.

### P0-3. SyncConsoleView в debug source-set, импортируется из main

**Файлы:** `MainActivity.kt:20`, `app/src/debug/java/.../SyncConsoleView.kt`

```kotlin
// MainActivity.kt:20
import com.aistudio.clinicsystem.ui.screens.SyncConsoleView

// MainActivity.kt:155-157
if (BuildConfig.DEBUG) {
    SyncConsoleView(viewModel = viewModel)
}
```

`SyncConsoleView.kt` находится в `app/src/debug/java/...` — debug source-set. В release-сборке debug source-set **не включается**, и Kotlin compiler не сможет разрешить импорт. R8 может удалить dead branch, но Kotlin compiler запускается до R8.

CI workflow `release-smoke` использует `continue-on-error: true` — ошибка silently проглатывается.

**Фикс:** Вынести `SyncConsoleView` в main source-set (с internal visibility) либо убрать импорт из `MainActivity.kt` и инжектить через debug-only механизм (например, debug `CompositionLocal` или `Intent` action).

### P0-4. release.yml не передаёт baseUrl/wsUrl/certPins

**Файл:** `.github/workflows/release.yml:54`

```yaml
- name: Build release AAB
  run: ./gradlew bundleRelease
  # ❌ нет -Pclinic.baseUrl=...
  # ❌ нет -Pclinic.wsUrl=...
  # ❌ нет -Pclinic.certPin1=... certPin2=...
```

`build.gradle.kts` падает в `https://INVALID.unset-base-url.example/` если `clinic.baseUrl` не передан.

**Следствие:** Release APK/AAB содержит `BuildConfig.BASE_URL = "https://INVALID.unset-base-url.example/"`, `BuildConfig.WEBSOCKET_URL = "wss://INVALID.unset-base-url.example/ws/queue"`, Certificate Pinning отключён (нет пинов).

**Фикс:** Добавить GitHub secrets (`CLINIC_BASE_URL`, `CLINIC_WS_URL`, `CLINIC_CERT_PIN_1`, `CLINIC_CERT_PIN_2`) и передавать их в `./gradlew bundleRelease`.

### P0-5. MainActivity role routing — `STAFF` vs реальные роли

**Файл:** `MainActivity.kt:123`


### High-4. Backend не имеет Play Integrity verification

`PlayIntegrityHelper` запрашивает токен, но **никуда его не отправляет**. Весь Play Integrity infrastructure в mobile client — dead code. Backend endpoint `POST /api/v1/mobile/attestation/play-integrity` не существует.

### High-5. Backend не имеет Idempotency-Key middleware для REST

`IdempotencyInterceptor` добавляет заголовок ко всем POST/PUT/PATCH/DELETE, но backend его игнорирует. Outbox retries могут приводить к дубликатам на сервере.

`domain/usecase/auth/` содержит 3 use cases + 13 unit-тестов на них. Ни один use case не вызывается в прод-коде — `AuthViewModel` обращается к `AuthRepository` напрямую.

### High-10. `registerInQueue` использует deprecated endpoint

### High-11. `observeMedicalRecordsWithSync` пишет lab results в medical_records
