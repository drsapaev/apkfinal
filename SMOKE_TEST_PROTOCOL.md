## Инструкция

1. Установите debug APK на реальное устройство или эмулятор
2. Убедитесь, что бэкенд запущен и доступен
3. Выполняйте сценарии по порядку
4. Отмечайте результат: ✅ Pass / ❌ Fail / ⚠️ Partial
5. При Fail — зафиксируйте шаг воспроизведения и logcat

## A. Authentication

| # | Шаг | Ожидаемый результат | Статус |

## B. Offline-First

### B1. Offline booking

| # | Шаг | Ожидаемый результат | Статус |
|---|---|---|---|
| 1 | Включить airplane mode | Индикатор "Нет подключения" | |
| 2 | Записаться на приём | Запись появляется локально, в SyncConsole — pending | |
| 3 | Отключить airplane mode | Outbox автоматически синхронизирует | |
| 4 | | Запись подтверждена сервером, pending удалён | |

### B2. Outbox retry

| # | Шаг | Ожидаемый результат | Статус |
|---|---|---|---|
| 1 | Выключить сеть | | |
| 2 | Создать 5 записей | 5 pending операций в очереди | |
| 3 | Выключить сервер | | |
| 4 | Включить сеть | Outbox пытается синхронизировать, получает ошибку | |
| 5 | | Статус FAILED, nextRetryAt установлен (backoff) | |
| 6 | Включить сервер | Через retry все 5 записей синхронизируются | |
| 7 | | Нет дубликатов (clientRequestId дедупликация) | |
| 8 | | Порядок сохранён (timestamp ASC) | |

### B3. Outbox dead letter

| # | Шаг | Ожидаемый результат | Статус |
|---|---|---|---|
| 1 | Создать запись с невалидными данными (например, несуществующий doctor_id) | | |
| 2 | Включить сеть | Outbox пытается отправить | |
| 3 | Сервер возвращает 400/422 | retryCount увеличивается | |
| 4 | После 5 попыток | Статус DEAD_LETTER, в логе "перемещена в DEAD_LETTER" | |

### B4. Stuck PROCESSING recovery

| # | Шаг | Ожидаемый результат | Статус |
|---|---|---|---|
| 1 | Начать синхронизацию | Статус PROCESSING | |
| 2 | Убить приложение (force stop) во время синхронизации | | |
| 3 | Открыть приложение снова | Stuck PROCESSING items recovered → PENDING | |
| 4 | Синхронизация возобновляется | | |
